# Participer à Cap Away

Les discussions, issues et pull requests doivent rester accueillantes et utiles.

- Respecter les personnes ; critiquer un comportement ou une proposition avec des faits.
- Décrire les bugs et désaccords de manière reproductible.
- Ne pas publier de données privées, secrets, trajets personnels ou contenus offensants.
- Ne pas harceler, discriminer ou solliciter commercialement les participants.
- Respecter la licence du code, les droits des données et la séparation de la marque.

Le mainteneur peut modérer un contenu inapproprié et demander de revenir au sujet. Pour un abus, utiliser les mécanismes privés de signalement de GitHub et les coordonnées que le mainteneur choisit de rendre publiques ; ne pas exposer des détails personnels dans une issue. Les vulnérabilités techniques relèvent de SECURITY.md.

Le but est d’améliorer une application utile, sans imposer un niveau d’expertise ou une disponibilité particulière aux contributeurs.
